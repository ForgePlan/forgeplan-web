# ADR-002: Use gRPC for internal service mesh

## Context

Helios control plane is split across 7 services (auth, billing,
tenant-mgmt, query-coordinator, alert-engine, webhook-dispatcher,
notification-fanout). Inter-service traffic is high-fanout, low-payload,
and frequently bidirectional (streaming alerts, query subscriptions).
RFC-002 (OpenTelemetry as canonical wire format) shifted the calculus:
both OTLP/gRPC and OTLP/HTTP exist; we pick one for internal mesh.

## Decision

**Selected: gRPC over HTTP/2 with protobuf for ALL internal service-
to-service communication. JSON/HTTP retained only at the public API
boundary.**

**Why selected**: streaming primitives, schema-driven backwards
compatibility, codegen for 4 supported languages, native compatibility
with OTLP/gRPC. Performance: 3.2× lower CPU on serialization at our
RPS; 40% smaller payloads on the wire.

## Alternatives Considered

| Option | Verdict | Why |
|--------|---------|-----|
| REST/JSON over HTTP/1.1 | Rejected | no streaming; expensive serialization at our RPS |
| gRPC | **Chosen** | streaming, schema, OTLP-native |
| GraphQL Federation | Rejected | wrong tool for internal mesh; great for client-facing APIs |
| MessagePack over WebSocket | Rejected | no schema evolution story; reinvents gRPC poorly |
| Apache Thrift | Rejected | community winding down; fewer recent features |

## Consequences

### Positive

- Schema as source of truth; breaking changes caught at codegen.
- Bi-directional streaming for query subscriptions and alert fanout.
- OTLP/gRPC alignment with RFC-002 — single wire stack.

### Negative (trade-offs)

- Browsers cannot speak gRPC natively → gateway translates at edge.
- Tooling: protobuf compiler in CI; regenerate clients on schema bump.
- Less curl-friendly debugging; mitigated by `grpcurl` + a debug HTTP
  reflection endpoint in dev environments.

### Risks

- Schema drift between services if proto repo is not the single source.
  Enforced by pre-commit hook + CI check.
- Cross-language string encoding edge cases (we hit one in v0.16 with
  Java/Kotlin clients on emoji in alert names).

## Invariants

- All internal RPCs declared in `proto/` monorepo path
- No hand-written stubs; all generated by buf
- Backwards compatibility: never reuse field numbers, never remove
  required fields without 2-version deprecation window

## Evidence Requirements

- p99 internal RPC latency stays under 5ms on warm path
- Schema bump compatibility: 0 consumer-breaking changes per quarter
  after the v0.18 protocol freeze
