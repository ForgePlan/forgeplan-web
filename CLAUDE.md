# @forgeplan/web — agent entry point

`@forgeplan/web` is a tiny **npm CLI** (`bin/forgeplan-web.mjs`) that
scaffolds a **pre-built SvelteKit app** into `.forgeplan-web/` of the
user's project. No `npm install` runs at user side: the package ships
`dist/` with its `node_modules/` baked in. The SvelteKit server shells
out to the host's local `forgeplan` CLI and streams read-only JSON to a
force-directed map UI.

Three surfaces in this repo:

- `bin/forgeplan-web.mjs` — Node ≥ 20.19 / 22.12 zero-dep CLI (init / start).
- `template/` — SvelteKit source. **Repo-internal**, NOT published.
- `dist/` — pre-built SvelteKit app (`vite build` + `npm install --omit=dev`).
  Generated by `scripts/build.mjs`. **Published**, copied verbatim into
  `.forgeplan-web/` by `init`.

Read this file, then `.claude/rules/00-index.md`, before planning any work.

## Source of truth

1. **Forgeplan workspace** (`.forgeplan/`) — single source of truth for
   *"what was decided, why, with what evidence"* AND *"what is being worked
   on"* via artifact lifecycle (`draft → active → superseded/deprecated/
   stale`). CLI: `forgeplan`. MCP: `.mcp.json`.
2. `.claude/rules/00-index.md` — enforced rules. Violating them is a defect
   unless an explicit `// TODO(...)` is present and the driving Forgeplan
   artifact's body justifies it.
3. `README.md` — public package contract (what `npx @forgeplan/web init -y`
   and `npx @forgeplan/web start` do). User-facing — keep in sync with the
   bin script.

This project does **not** use Linear or any external task tracker. The
Forgeplan artifact lifecycle is the queue.

## Architecture in one paragraph

`bin/forgeplan-web.mjs` runs in the user's project directory. `init`
(1) verifies `.forgeplan/` exists and the `forgeplan` binary is on
`PATH`, (2) copies the package's bundled `dist/` → `.forgeplan-web/`
(skipping existing files unless `--force`), (3) writes
`forgeplan-web.json` with `workspaceRoot` so the SvelteKit server knows
where to spawn `forgeplan`. **No `npm install` runs at user side** —
`dist/` already contains `node_modules/` populated with `--omit=dev`.
`start` spawns `node .forgeplan-web/index.js` with `PORT`/`HOST`/
`FORGEPLAN_CWD`/`FORGEPLAN_BIN` env. The SvelteKit server exposes
`/api/*` endpoints that `spawn` the host's `forgeplan <subcommand> --json`
in `FORGEPLAN_CWD` (default: directory recorded by init). The browser
polls every 10 s and renders a force-directed graph.

## Methodology (Forgeplan)

```
OBSERVE → ROUTE → SHAPE → BUILD → PROVE → SHIP
```

| Phase | Action | Command |
|---|---|---|
| Observe | restore context, find blind spots | `forgeplan health` |
| Route | decide depth | `forgeplan route "<task>"` |
| Shape | create + validate artifacts | `forgeplan new <kind>` ; `forgeplan validate <id>` |
| Reason | ADI hypotheses (Standard+, mandatory for Deep+) | `forgeplan reason <id>` |
| Build | code + tests | (Node CLI + Svelte) |
| Prove | evidence + R_eff | `forgeplan new evidence` ; `forgeplan link` ; `forgeplan score` |
| Ship | activate + PR + merge | `forgeplan activate` ; `gh pr create` |

Depth: **Tactical** (just code) / **Standard** (PRD+RFC) / **Deep**
(PRD+Spec+RFC+ADR) / **Critical** (Epic+stack with adversarial review).
Default is Tactical; escalate per `.claude/rules/11-forgeplan-required.md`.

Standard+ work is not done until: artifact filled + validated, evidence
linked with structured fields, **R_eff > 0**, artifact `active`, PR merged.

### Hint protocol (parse and follow)

Every `forgeplan` (CLI or MCP) output ends with a deterministic next-action
marker. Execute the suggested command **verbatim** — do not paraphrase, do
not invent placeholders.

| Marker | Action |
|---|---|
| `Next: <full command>` | run as-is |
| `Or: <full command>` | only if `Next:` blocks |
| `Wait: <condition>` | retry after condition |
| `Done.` | terminal — move on |
| `Fix: <full command>` | error remediation |

JSON / MCP put the same value in `_next_action`.

### R_eff (the math you must know)

`R_eff = min(evidence_scores)` — **weakest link, never average**.
EvidencePack body MUST contain a `## Structured Fields` section with
`verdict`, `congruence_level`, `evidence_type`. Without them the parser
silently sets CL0 → R_eff collapses to 0.1.

## Common commands

```bash
# Build the publishable artifact (runs vite build + emits dist/)
npm run build

# Local smoke test of the bin script against a scratch dir with .forgeplan/
mkdir -p /tmp/scratch/.forgeplan && cd /tmp/scratch && \
  node /path/to/forgeplan-web/bin/forgeplan-web.mjs init -y --force && \
  node /path/to/forgeplan-web/bin/forgeplan-web.mjs start

# Template dev loop (HMR on raw sources, NOT dist/)
cd template && npm install && npm run dev   # → http://localhost:5174

# Publish (do NOT run without explicit user approval; deny-listed in hooks)
# `prepublishOnly` runs `node scripts/build.mjs` so dist/ is fresh.
npm publish

# Forgeplan
forgeplan health             # session-start sanity check
forgeplan list               # all artifacts
forgeplan graph              # mermaid dependency graph
forgeplan stale              # artifacts past valid_until
forgeplan blindspots         # decisions without evidence
```

After `git clone`: `forgeplan init -y && forgeplan scan-import` rebuilds the
Lance index from the markdown files (already initialised — `init` is idempotent).

## Hard requirements

1. **Host writes are bounded to `.forgeplan-web/` + a single
   `.gitignore` append.** The bin script writes only inside
   `.forgeplan-web/` plus an append-only, idempotent ignore line in the
   host's `.gitignore` (skipped via `--no-gitignore`). It never edits
   the host's `package.json`, `.forgeplan/`, lockfiles, or anything
   else. See ADR-001 + rule 20.
2. **Template purity.** `template/` is repo-internal (NOT published). It
   must remain copy-safe so the build pipeline can produce a self-
   contained `dist/`: no symlinks, no absolute paths, no references to
   this repo's root `package.json`, no committed `node_modules/`.
   Runtime deps live in `template/package.json#dependencies`; build-only
   tooling in `devDependencies`.
3. **Read-only proxy.** SvelteKit endpoints in `template/src/routes/api/`
   only invoke `forgeplan <cmd> --json` and stream stdout. They MUST NOT
   shell out to mutating subcommands (`new`, `link`, `activate`, `release`,
   `delete`, `claim`, …) — the UI is a viewer, not an editor.
4. **Zero runtime deps in `bin/`.** The init script runs under `npx` before
   the user has installed anything; it must use Node built-ins only
   (`node:fs`, `node:child_process`, `node:path`, `node:url`).
5. **Node engines pinned.** Match `package.json#engines`
   (`^20.19.0 || >=22.12.0`). Do not lower without an ADR.
6. **Comments policy** — see `.claude/rules/10-comments-policy.md`.
   `TODO(reason)` / `FIXME(reason)` for cut corners, edge cases,
   suppressed errors. No comments restating *what* the code does.
7. **Forgeplan artifact required for Standard+ work** — see rule 11.
   `R_eff > 0` and `active` before merge.

## Process

1. **Observe.** `forgeplan health` first. Fix blind spots / orphans before
   new work.
2. **Route + shape (Standard+).** `forgeplan route "<task>"`. Create the
   recommended artifacts (PRD / Spec / RFC / ADR), fill MUST sections
   immediately (no stubs), `forgeplan validate`.
3. **Reason (Standard+).** `forgeplan reason <id>` — at least 3 hypotheses.
   Mandatory at Deep+.
4. **Build.** Read rules + obey hard requirements. Test the bin script
   against a scratch directory after every change. Mark `// TODO(...)` for
   any cut corner.
5. **Prove.** `forgeplan new evidence "..."`; fill the body **including
   `## Structured Fields`** (`verdict` / `congruence_level` /
   `evidence_type`); `forgeplan link EVID-X <id> --relation informs`;
   `forgeplan score <id>`. Aim for `R_eff > 0`.
6. **Ship.** `forgeplan activate <id>`. Open PR with `Refs: <id>` in the
   body. After merge: short summary in the artifact body.

Tactical work (one-line fixes, formatting, README typos) skips steps 2, 3,
5 and goes observe → code → PR.

## Project-local skills

Project-scoped agent skills live in `.claude/skills/`. Load the relevant
SKILL.md when its trigger applies; it overrides any conflicting global
skill of the same name.

| Skill | Trigger | Source |
|---|---|---|
| [svelte-code-writer](.claude/skills/svelte-code-writer/SKILL.md) | Editing `.svelte` / `.svelte.ts` / `.svelte.js` files in `template/`. Provides `npx @sveltejs/mcp` lookups + autofixer. | Vendored from `sveltejs/ai-tools` |
| [svelte-core-bestpractices](.claude/skills/svelte-core-bestpractices/SKILL.md) | Writing or reviewing Svelte 5 code (runes, events, snippets, styling). | Vendored from `sveltejs/ai-tools` (see TODO inside — `references/` not yet vendored) |
| [feature-sliced-design](.claude/skills/feature-sliced-design/SKILL.md) | Deciding directory placement for `template/src/**`, reviewing import boundaries, refactoring for FSD compliance. SvelteKit-specific guidance included. | Hand-rolled from <https://feature-sliced.github.io/documentation/> — no published agent skill exists |

When working in `template/` (the SvelteKit source), load both
`svelte-core-bestpractices` and `feature-sliced-design`. When generating
or refactoring `.svelte` files, additionally load `svelte-code-writer` and
run the autofixer before committing.
