## Measurement

Two scratch-directory smoke runs against `bin/forgeplan-web.mjs` after the
`update` subcommand was added. The runs simulate the three behaviours the
RFC promised: (1) idempotent no-op when bundled and installed versions
match, (2) full refresh when versions differ or `--force`, and (3) stale-
file removal across versions.

Procedure (run 1, same-version):

```bash
mktemp -d → mkdir .forgeplan → init -y
echo "// CORRUPTED" > .forgeplan-web/index.js
node bin/forgeplan-web.mjs update                      # expected no-op
node bin/forgeplan-web.mjs update --force              # expected refresh
```

Procedure (run 2, simulated upgrade):

```bash
mktemp -d → mkdir .forgeplan → init -y -q
# Mutate forgeplan-web.json to record version 0.0.5
# Drop a marker file STALE-FROM-OLD-VERSION.txt into .forgeplan-web/
node bin/forgeplan-web.mjs update                      # expected v0.0.5 → v0.1.2
test ! -f .forgeplan-web/STALE-FROM-OLD-VERSION.txt    # stale must be gone
rm -rf .forgeplan-web && node bin/forgeplan-web.mjs update  # expected error
```

## Result

Run 1:
- `init -y` wrote `forgeplan-web.json` with `version: 0.1.2`,
  `createdAt: 2026-05-04T12:47:43.359Z`, `updatedAt` equal to
  `createdAt`.
- `update` (no flags) printed `✓ already at v0.1.2` and exited 0
  without re-copying. Mutated `index.js` was **not** restored at this
  point (correct — no-op).
- `update --force` printed `→ updating ... (v0.1.2 → v0.1.2)` and
  `✓ updated to v0.1.2`. Resulting `forgeplan-web.json`:
  - `createdAt` unchanged at `2026-05-04T12:47:43.359Z` (preserved)
  - `updatedAt` bumped to `2026-05-04T12:47:43.897Z`
  - `version` `0.1.2`, `workspaceRoot` preserved
- `index.js` first line restored to `import http from 'node:http';`
  (mutation gone).
- `.gitignore` contains exactly one block: `# generated by @forgeplan/web init` + `.forgeplan-web/` — `update` did not touch it (rule 20 honored).

Run 2:
- After tampering `version` → `0.0.5` and dropping a stale marker,
  `update` printed `→ updating ... (v0.0.5 → v0.1.2)` and `✓ updated to v0.1.2`.
- `STALE-FROM-OLD-VERSION.txt` was removed (`OK: stale removed`).
- `createdAt` preserved (`2026-05-04T12:47:59.677Z`); `updatedAt` bumped
  (`2026-05-04T12:48:00.162Z`).
- After `rm -rf .forgeplan-web`, `update` exited with code `1` and
  message: `no scaffold at <path>. Run \`npx @forgeplan/web init\` first.`

Static check: `grep -E "from ['\"][^n]" bin/forgeplan-web.mjs` returns no
matches → only `node:*` imports → rule 23 (zero runtime deps in `bin/`)
holds. `node --check bin/forgeplan-web.mjs` exits 0.

## Interpretation

All five RFC-002 acceptance behaviours observed:

1. ✅ One-shot upgrade: `update` makes `.forgeplan-web/` match bundled
   `dist/` exactly, including removal (stale marker file gone).
2. ✅ Version visibility: `from vX → to vY` shown when versions differ.
3. ✅ Idempotent no-op: `update` exits cleanly with `already at v…`
   when current.
4. ✅ Provenance preserved: `workspaceRoot` and `createdAt` survive;
   `version` and `updatedAt` bumped.
5. ✅ Host isolation: `update` did not modify `.gitignore`, the host
   `package.json`, or anything outside `.forgeplan-web/`.

The `--force` path also verifies the no-op gate is bypassable, which is
important for the "I think my install is corrupt, just re-do it" use
case.

## Congruence Level Justification

CL3 (same-context, penalty 0.0). The measurements were produced by
running the exact bin script that the npm tarball will ship — same
Node version, same `dist/`, same code paths a user invokes via
`npx @forgeplan/web update`. There is no platform translation between
the test rig and production: the test rig **is** production.
